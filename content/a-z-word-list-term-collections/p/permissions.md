## permissions

Use *permissions* to refer to operations associated with a specific shared resource (such as a file, directory, or printer) that the system administrator authorizes for individual user accounts or administrative groups.

In the context of AI, *permissions* refer to the level of authorization that an administrator gives to an AI agent during configuration so that the agent can access specific information or carry out its tasks.

## Guidelines

If you refer to a named permission, use title-style capitalization with no special formatting.

Don't use *permissions* as a synonym for:

- *privilege*, which is a specific kind of elevated permission.
- *permission record*, which is information that shows what permissions are granted and to whom.
- *access*, which is the ability, not the authorization.
- *identity*, which is a user or an account.
- *role*, which is a collection of permissions.
- *service principal*, which is an identity that represents an application or service.

## Examples

- Setting the Traverse Folder permission on a folder doesn't automatically set the Execute File permission on all files within that folder.
- Grant Read, Read and Execute, and List Folder Content permissions to the Users group.
- Whenever possible, assign permissions to groups instead of users.
- We recommend that you use roles with the fewest permissions.
